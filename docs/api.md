# Complete REST API Specification — Atomic-Pay

This document provides the complete API reference for the **Atomic-Pay** distributed banking and financial transaction system. All API endpoints use standard JSON payloads, follow unified response wrappers, and support distributed tracing via correlation IDs and idempotency headers.

---

## 🌐 System Architecture & Base URLs

When running locally, frontend calls are proxied through Vite or API Gateway (`http://localhost:8080/api/v1`). Individual microservices can also be accessed directly on their respective ports:

| Service Name             | Port   | Base Path                  | Description                                         |
| :----------------------- | :----- | :------------------------- | :-------------------------------------------------- |
| **API Gateway**          | `8080` | `/api/v1/*`                | Unified entry point & routing proxy                 |
| **Auth Service**         | `8084` | `/api/v1/auth`             | User registration, authentication, JWT tokens       |
| **Account Service**      | `8081` | `/api/v1/accounts`         | Digital wallet accounts & beneficiaries             |
| **Transaction Service**  | `8082` | `/api/v1/transfers`        | Idempotent transfer execution & Saga orchestrator   |
| **Ledger Service**       | `8083` | `/api/v1`                  | Double-entry financial ledger & mathematical audits |
| **Notification Service** | `8085` | `/api/v1/notifications`    | Real-time user alert inbox & event streaming        |
| **Audit Service**        | `8086` | `/api/v1/admin/audit-logs` | Compliance log aggregation & security trail         |
| **Analytics Service**    | `8087` | `/api/v1/analytics`        | Real-time transaction metrics & reporting           |

---

## 🔑 Common Request Headers

| Header Name          | Type          | Required                  | Description                                                                          |
| :------------------- | :------------ | :------------------------ | :----------------------------------------------------------------------------------- |
| `Authorization`      | String        | Conditional               | `Bearer <JWT_TOKEN>` for authenticated routes.                                       |
| `Content-Type`       | String        | Yes                       | Must be `application/json` for POST/PATCH requests.                                  |
| `Idempotency-Key`    | String (UUID) | Required for `/transfers` | Unique UUID generated by frontend per transfer request to prevent duplicate charges. |
| `X-User-Id`          | String (UUID) | Conditional               | Authenticated User ID (passed automatically by Gateway).                             |
| `X-Correlation-ID`   | String        | Optional                  | Distributed tracing ID (e.g., `corr-1791234000-abcde`).                              |
| `X-Simulate-Failure` | String        | Optional (Testing)        | Options: `FAIL_CREDIT`, `DELAY_CREDIT`, `FAIL_DEBIT` to simulate failure scenarios.  |

## 📦 Unified Response Wrapper Format

Every API endpoint returns responses enclosed within a standard `ApiResponse<T>` envelope.

### 1. Success Response (HTTP 200 / 201)

```json
{
  "success": true,
  "data": { ... },
  "timestamp": "2026-10-07T06:00:00Z",
  "requestId": "corr-1791234000-abcde"
}
```

### 2. Error Response (HTTP 4xx / 5xx)

```json
{
  "success": false,
  "error": {
    "code": "INSUFFICIENT_BALANCE",
    "message": "Sender account does not have sufficient available balance for this transfer",
    "details": {
      "requestedAmount": 1000.0,
      "availableBalance": 250.0
    }
  },
  "timestamp": "2026-10-07T06:00:00Z",
  "requestId": "corr-1791234000-abcde"
}
```

## ⚡ Error Codes Reference

| Error Code                    | HTTP Status          | Description                                                                     |
| :---------------------------- | :------------------- | :------------------------------------------------------------------------------ |
| `IDEMPOTENCY_KEY_REQUIRED`    | `400 Bad Request`    | Missing `Idempotency-Key` header in transfer request.                           |
| `INVALID_REQUEST`             | `400 Bad Request`    | Missing required parameters or payload validation failure.                      |
| `INSUFFICIENT_BALANCE`        | `422 Unprocessable`  | Sender account does not have sufficient available funds.                        |
| `ACCOUNT_NOT_FOUND`           | `404 Not Found`      | Sender or receiver account ID does not exist.                                   |
| `SAME_ACCOUNT_TRANSFER`       | `400 Bad Request`    | Sender and receiver account IDs cannot be identical.                            |
| `DUPLICATE_IDEMPOTENCY_KEY`   | `200 OK` (Replay)    | Replays previously processed transaction response.                              |
| `SAGA_COMPENSATION_TRIGGERED` | `500 Internal Error` | Transaction failed during credit phase; backward compensation executed cleanly. |
